# Stock counter and motor clocks

Status: **prototype, offline only**, 2026-11-22. This extends the
[compiled Sensa publisher](COMPILED_SENSA_PUBLICATION.md) without changing
the compiled module. No controller access or firmware flashing.

## Counter provenance

The publisher reads `0x200139F4`. In the pinned NXP v2.04.00 image this
counter is advanced by MRT0 IRQ9, vector `0x1485C`, rather than SysTick.
The stock handler increments phase word `0x20013A00` at `0x148CC`; every
eight delivered interrupts it increments the publisher's counter at
`0x148E0`. The replay checks both writer PCs and IPSR on every CPU store.
The host supplies an initial state but does not advance these RAM counters.

Stock initializer `0x22F94` requests its clock through `0xA9F4`, sets
MRT channel 0 to repeat with interrupts enabled, assigns IRQ priority
`0x40` and loads an interval of 12,000 clocks. In the existing 96 MHz
clock fixture, that means a nominal 125 microseconds per expiration
and one counter increment per millisecond **if all interrupts arrive**.
This is a register-derived virtual schedule, not measured device timing.

`nxp_mrt_model.py` models four 24-bit channels, interval-minus-one
readback, deferred and forced reload, repeat/one-shot modes, RUN and W1C
flags, and interrupt enable. It rejects stall/reserved and multitask
modes instead of inventing behavior. The supported register contract
comes from NXP's [LPC54605 header](https://github.com/nxp-mcuxpresso/mcux-sdk/blob/master/devices/LPC54605/LPC54605.h)
and [MRT driver](https://github.com/nxp-mcuxpresso/mcux-sdk/blob/master/drivers/mrt/fsl_mrt.h).

## Shared virtual schedule

`nxp_ctimer_clock.py` reads the already initialized CTIMER2/3 prescaler,
MR0, counter, enable and reset-on-match configuration. The covered steady
MR0 configuration yields periods of 24,000 and 96,000 supplied clocks:
250 microseconds and 1 millisecond in this fixture. Reconfiguration and
capture/other-match operations fail explicitly. Initial prescaler phase
must be zero. Clock gating and changes to the PLL are outside this model.

The clock stage advances MRT and both motor timers together, delivers
their original vectors through the architectural M4/FP exception model,
and executes the original DMA completion handler, compiled tap/DSP/frame
publisher and stock decoder/PWM code. It calls the foreground Sensa
callsite once per supplied DMA block; it does not run the full main loop.
CPU instruction execution consumes no virtual clock cycles. FIFO transfers
are supplied block copies, and nominal DMA completion events are still
test inputs. This does not establish bus timing or ISR worst-case time.

The stock generic timer ISR and its callback both write the same W1C
bit. The model counts these writes separately from events whose pending
flag was actually cleared. A second clear cannot invent another event.

Four continuous cases cover synthetic stereo, a 24-block USB pause,
and 96-slot windows from each existing wired/dongle capture (start 3000).
Each preserves 18,432 PCM bytes. The steady cases execute 1,272 MRT,
636 CTIMER2 and 159 CTIMER3 events, with 2,226 checked exception returns.
The pause case executes 1,464/732/183 events, 2,562 checked returns and
has the expected eight-block underrun gap. Both palms have a positive
PWM control, audio never activates triggers, and draining emits a stop.
Activity and the final eight duty snapshots are compared with separate
silent-PCM replays on the same schedules. Startup duty `(120,120,0,0)`
is not assumed to be steady-state silence. The comparison deliberately
rejects all-silent output, a missing left palm and a stuck final duty.
Two silent reference traces are reused across the four active cases.
Both references end at `(288,288,0,0)` in this fixture; each active trace
matches its reference for the final eight observations.
No host-built candidate Sensa packets or host counter updates are used.
Captured payload bytes are authentic historical host audio; GIP sequence
and arrival times are regenerated by the fixture. They are not proof of
game-authored DualSense input.

## Missed ticks are retained as a limitation

A peripheral flag and NVIC pending bit are not queues. Sixteen timer
expirations while delivery is masked become one handler invocation,
with fifteen coalesced expirations. PRIMASK, BASEPRI and NVIC-disabled
cases exercise this behavior. Phase and counter wrap are also tested.

Without losses, the foreground publisher stops at counter 250 after
250,000 supplied microseconds. Injecting 2,000 microseconds into its
protected packet copy coalesces fifteen events; the counter reaches
250 after **252,000 supplied microseconds** instead. The existing
250-counter-tick check therefore is not an independent wall-clock
watchdog. These values describe an intentionally supplied delay, not
measured latency or a claim that stock decoding takes 2 ms. Busy stock
decoding can separately defer a stop, as the publication stage records.
The replay must not conceal lost ticks with host-side counter catch-up.

Register tests include ten MRT checks/five rejections and four motor
checks/two rejections. They also run with Python optimization enabled;
new correctness guards use explicit checks rather than removable asserts.

## Reproduce and next boundary

```powershell
$env:PYTHONPATH='TestResults/firmware-lab/deps'
python -B tools/firmware/replay_nxp_clock.py <Dev2FW.bin> <audio_haptics.bin>
# Add both --wired-pcm-trace and --dongle-pcm-trace for recorded windows.
# The complete suite includes this as nxp-clock.
```

Next close foreground scheduling and its other stock tasks, investigate
masked worst-case time and an independent elapsed-time safety source,
and implement actual runtime controls plus non-Sensa GIP rumble/trigger
arbitration. Whole-board peripherals, Telink synchronization, USB/console
authentication, physical timer clocks, validated memory placement,
bootloader image acceptance and recovery remain separate open boundaries.
This module is not a complete or loadable controller firmware.
